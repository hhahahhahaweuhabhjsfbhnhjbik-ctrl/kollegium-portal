# Портал Коллегии адвокатов Mirror GTA 5 RP

Локальный Node.js-портал с аккаунтами граждан и состава, одноразовыми приглашениями, восстановлением пароля, базой законов, заявками, экзаменами, переаттестациями, Discord-синхронизацией, поручениями, календарём, архивом документов и отслеживанием исков.

## Требования

- Node.js 24 или новее
- npm, который устанавливается вместе с Node.js

SQLite входит в Node.js, а `discord.js` используется для подключения бота к Discord Gateway.

## Структура проекта

Интерфейс разделён на слои: разметка, оформление, данные и логика лежат в разных файлах, поэтому HTML содержит только визуальную структуру.

```
advokate.html          разметка портала: только элементы и классы, без стилей и скриптов
web/css/base.css       проверенная раскладка всех разделов
web/css/theme.css      визуальная тема: палитра, поверхности, шапка, навигация, карточки
web/css/awards.css     витрина «Элита коллегии: высшие награды»
web/js/core/dom.js     помощники для работы с DOM
web/js/data/config.js  статические справочники: роли, ступени, схемы документов
web/js/views/           отдельные компоненты интерфейса (витрина наград)
web/js/app.js          состояние интерфейса, обращения к API и отрисовка разделов
web/data/              контент в JSON (каталог высших наград)
server.mjs             HTTP API, база SQLite, авторизация и маршруты
webhooks.mjs           доставка уведомлений в Discord: очередь, повторы, лимиты
discord-bot.mjs        бот Discord: роли, каналы, команды, кнопки
tools/                 проверки и вспомогательные скрипты
```

Сервер отдаёт файлы из `web/` по путям `/web/...`, сам каталог защищён от выхода за свои пределы. Политика безопасности контента разрешает скрипты только с этого же источника — инлайновый код в разметке больше не нужен.

## Первый запуск

В PowerShell из папки проекта:

```powershell
npm.cmd install
npm.cmd run create-admin
npm.cmd start
```

Первая команда запросит логин, отображаемое имя и пароль для первого аккаунта ГКА. Пароль хранится только в виде криптографического хеша. Затем откройте <http://localhost:3000>.

Не открывайте `advokate.html` напрямую через `file://`: интерфейсу нужен запущенный сервер API.

## Windows-приложение

Можно собрать один установщик EXE для двух режимов: сервер ГКА и клиент сотрудника.

```powershell
npm.cmd install
npm.cmd run desktop:build
```

Установщик появится в папке `release`. На ПК ГКА выберите режим «Сервер ГКА»: приложение создаст первую учётную запись ГКА, хранит SQLite в каталоге данных пользователя Windows и запускает портал с Discord-ботом на `127.0.0.1:3000`. Не запускайте на этом ПК одновременно `npm start` и режим «Сервер ГКА»: оба процесса используют один порт, а второй запуск завершится понятной ошибкой. Этот ПК должен оставаться включённым, пока нужны общие обращения. На остальных компьютерах установите тот же EXE и выберите «Рабочее место сотрудника», затем укажите адрес сервера.

EXE не может сам обеспечить доступ из интернета без постоянно работающего сервера. Для подключения из других мест настройте на ПК ГКА HTTPS reverse proxy или HTTPS-туннель к `127.0.0.1:3000`; не публикуйте порт приложения напрямую по HTTP. В режиме «Сервер ГКА» при заданном внешнем HTTPS-адресе приложение открывает портал через этот адрес, а Discord callback автоматически строится как `<внешний адрес>/api/discord/callback`. Добавьте показанный мастером callback в Discord Developer Portal → OAuth2 → Redirects. При смене адреса (в частности, Quick Tunnel) обновите его и там. Удалённые клиентские EXE принимают только HTTPS-адреса. Адрес сервера и каталог данных показываются мастером настройки. Чтобы включить Discord-интеграцию в установленном приложении, поместите `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` и при необходимости настройки бота/webhook в локальный `.env` в показанном каталоге данных; секреты не входят в установщик и не должны отправляться в чат.

Перед миграцией с Node.js-версии остановите старый сервер и сделайте резервную копию `data/portal.sqlite`. Затем скопируйте `data/portal.sqlite` в каталог данных, показанный мастером, под именем `portal.sqlite`; если в базе уже есть ГКА, мастер обнаружит аккаунт и не создаст новый. Не копируйте базу, пока старый сервер работает.

## Приглашение и доступ

1. Гражданин может зарегистрироваться без приглашения; аккаунт получает ограниченную роль «Гражданин».
2. Состав регистрируется только по одноразовому коду ГКА.
3. Каждый код подходит для одной регистрации. Новый участник получает роль стажера КА и ждёт одобрения.
4. ГКА активирует участника и назначает ему игровую роль.
5. Сотрудник должен привязать Discord через OAuth до доступа к рабочим разделам; гражданам привязка не требуется. Страница статуса, привязка и выход остаются доступны до подключения.

Гражданин может выбрать активного адвоката или отправить обращение без выбора. Запрос может взять выбранный адвокат (либо руководство); оценка доступна только автору после закрытия обращения и отправляется один раз. Гражданин также может подать отдельную заявку на вступление с Discord-ником, именем персонажа и номером паспорта. Одобрить её и принять аккаунт в роль стажёра может только ГКА. Роль сотрудника не выбирается и не повышается самим пользователем. ЗГКА могут назначать переаттестации и рассматривать разрешенные им заявки; создание приглашений и управление составом остаётся у ГКА.

### Техническое управление через Discord

В Discord Developer Portal → приложение бота → **Bot** включите **Message Content Intent**. После этого владелец или администратор сервера может отправить боту `!tech on` (показать страницу техработ), `!tech off` (вернуть сайт) или `!tech restart` (перезапустить портал и бота). Команда рестарта завершает процесс штатно; Docker Compose запускает контейнер снова при включённой политике `unless-stopped`. `/api/health` остаётся доступен во время техработ.

Запросы юристов на совместную практику доступны адвокатам, старшим адвокатам, ЗГКА и ГКА. Те же роли могут брать обращения граждан в работу; гражданские обращения также доступны в разделе «Практика».

Для повышения сотрудник открывает свой этап, знакомится с краткой подготовкой и сдаёт тест. Стажёр после успешного теста становится юристом; юрист и адвокат дополнительно отмечают готовность к обзвону. Руководство видит готовность в журнале Discord и подтверждает обязательные условия перед сменой роли. Готовность можно отложить и отметить позднее в заявке.

## Возможности

- Gemini-помощник на страницах «Законодательная база» и «Система исков»: консультации по загруженным законам, генерация описательной и просительной частей документов с пометками для недостающих данных. Серверный ключ задаётся переменной `GEMINI_API_KEY`; модель можно выбрать через `GEMINI_MODEL` (по умолчанию `gemini-3.5-flash-lite`) с резервом `GEMINI_FALLBACK_MODEL=gemini-2.5-flash`. При перегрузке сервер повторяет запрос и последовательно пробует резервные модели. Ключ не передаётся браузеру.
- Этапы повышения по требованиям Коллегии: стажёр → юрист (лекция и проверка), юрист → адвокат (норма вызовов от ГКА, пробный иск и проверка), адвокат → старший адвокат (25 вызовов, 5 совместно с юристом, принятое исковое заявление, обзвон, свободное место и решение ГКА).
- Чек-листы руководителей проверяются сервером до смены роли. Для повышения до старшего адвоката требуется отдельный отчёт; экзамен не может автоматически присвоить эту роль.
- Фото и PDF можно прикрепить к заявке или отчёту: до 5 файлов, не более 2 МБ каждый и 5 МБ суммарно. Файлы хранятся в SQLite и доступны автору, ГКА и ЗГКА.
- ГКА или ЗГКА задаёт число вызовов для перехода «Юрист → Адвокат» в разделе управления порталом.
- Пошаговые экзамены по ступени сотрудника и отдельные тесты по АК, ПК, УК, ЗОТ и Закону об адвокатуре; ответы проверяются сервером.
- Три уровня RP-практики с постоянной блокировкой правильно пройденных кейсов и отдельный полноэкранный AI Case: ветвящиеся диалоги с офицером, реакциями, разбором ответов и управляемыми звуковыми эффектами.
- Назначение и прохождение переаттестаций.
- Генератор форумных документов в BBCode с предпросмотром и локальным скачиванием.
- Сохранение черновиков в серверном архиве; черновики не влияют на статистику.
- Отправка опубликованной темы форума на проверку руководству. Только подтверждённая публикация учитывается в профиле.
- Подача исков из конструктора документов с обязательной форумной ссылкой; этапы дела открываются после проверки ссылки.
- Поиск с контекстом и подсветкой по АК, УК, ПК, ЗОТ, Закону об адвокатуре, Уставу, Дорожному и Трудовому кодексам, Этическому кодексу, законам о документообороте и Департаменте юстиции. Явные ссылки между кодексами открываются из результата поиска.
- На странице судебных дел EXE открывает Верховный суд форума в отдельном изолированном окне. Пользователь входит непосредственно на сайте; портал не получает пароль и не копирует содержимое форума.
- Отдельная страница «Мой профиль»: роль, стаж, подтверждённые вызовы, документы, дела, обращения, задачи, история приёма/повышений/увольнений/восстановлений, экзамены, переаттестации, отсутствие, взыскания, достижения, награды и отзывы. Кадровая история фиксируется с момента обновления и не выдумывается задним числом. В профиле можно сохранить ссылку на аккаунт форума GTA5RP; ГКА вручную отмечает её проверенной. Это ссылка на профиль, не OAuth-привязка форума.
- Каталог достижений с выдачей за проверенные метрики и ручными достижениями, индивидуальные награды от руководства и страницы личного списка/каталога.
- Витрина «Элита коллегии: высшие награды» — десять статусных отличий с лавровыми медальонами, описанием условия и меткой сложности: от «Легко» до «Легендарно». Награды вручает руководство, витрина автоматически отмечает уже полученные и показывает счётчик «N из 10».
- Рейтинг адвокатов за 7 дней, 30 дней и всё время; баллы основаны на одобренных документах, закрытых обращениях, исках с подтверждённой публикацией на форуме, принятых руководством поручениях и оценках граждан. Формулу может настроить ГКА; изменения сохраняются в истории.
- Кадровый резерв с отметкой готовности сотрудника к следующей ступени; заявки на отпуск и отсутствие с одобрением/отклонением и комментарием руководства.
- Внутренние характеристики сотрудников по направлениям с оценкой и заметкой; API и пункт меню доступны только ГКА и ЗГКА.
- Академия адвокатуры с лекциями, пособиями и заданиями по категориям; руководство создаёт, редактирует и удаляет материалы, состав ищет и фильтрует их.
- Рабочее пространство сотрудников с поручениями: руководство создаёт задания, назначает нескольких исполнителей, сроки, приоритеты и файлы; исполнители принимают и выполняют задания, отправляют на проверку, а руководство принимает результат или возвращает его на доработку. История действий и вложения хранятся в SQLite; доступ к заданию ограничен его исполнителями и руководством.
- Календарь судебных заседаний, собеседований, экзаменов, переаттестаций, совещаний и обучения с режимами просмотра по дням, неделям и месяцам. Руководство назначает ответственного, участников или доступ всем сотрудникам и отмечает проведение/отмену; сотрудники видят только общие или назначенные им события. Бот отправляет каждому привязанному участнику личное напоминание примерно за сутки и за час; успешные отправки сохраняются в SQLite и не дублируются.
- История обращений и судебных дел, сроки и приоритеты, переназначение обращений руководством. Закрытые обращения и дела остаются в архиве. Срок и приоритет закрытых дел изменить нельзя.
- Аналитика для ГКА и ЗГКА за 7/30/90 дней или всё время: фактический состав, дела по статусам, документы, обращения, оценки, кадровые события и динамика. Приём, увольнения и восстановления учитываются только с момента начала записи кадровой истории; события до обновления нельзя достоверно восстановить. Победы/поражения не выводятся: статус «решение внесено» сам по себе не подтверждает исход.
- ГКА может начать новую неделю: завершённые мероприятия, рассмотренные внутренние заявки, обработанные отсутствия и выговоры перемещаются в архив без удаления. Незавершённые заявки и запланированные мероприятия остаются активными; состав, достижения, отзывы, рейтинг, дела и документы не затрагиваются. Предпросмотр показывает точное число записей, история фиксирует автора и время, а архив можно восстановить.
- Домашняя панель показывает доступные по роли реальные обращения, документы, дела, поручения и события; профиль, рейтинг и показатели не заполняются демонстрационными данными. Поиск открывает найденные разделы, а календарь и боковую навигацию можно управлять прямо с панели.
- Кликабельные профили состава со статистикой и рейтингом; личная почта и тексты документов не публикуются.
- Каталог адвокатов для граждан: выбор специалиста при обращении, приватный чат и передача контакта только после привязки Discord. Портал формирует адрес вида `ник@sa.com` и рядом показывает исходный Discord-ник; личная почта аккаунта не раскрывается. Закрыть обращение может только назначенный адвокат; после этого гражданин может один раз оставить оценку от 1 до 5.
- Журнал выговоров с основанием и фото: взыскание видит сотрудник, которому оно выдано, а полный журнал доступен ГКА и ЗГКА. Бот отправляет карточку с фото в личные сообщения привязанному Discord-аккаунту, а журнал выговоров дублируется webhook в закрытый канал руководства. Webhook сам по себе не умеет писать в личные сообщения; если личка закрыта или Discord не привязан, взыскание всё равно сохраняется на сайте и в канале журнала.
- Одноразовое восстановление пароля по коду, который выдаёт ГКА после проверки владельца аккаунта; код действует 30 минут.
- Привязка Discord сотрудников через OAuth обязательна для доступа к рабочим разделам; гражданам она не требуется. После привязки бот может синхронизировать роль и ник вида `[Адвокат] Имя Фамилия`.
- Один Discord-аккаунт может быть привязан только к одному аккаунту портала: занятый Discord отклоняется, а сменить привязку у аккаунта может только ГКА. Вместе с ограничением частоты регистрации и входа это не даёт массово создавать аккаунты и обходить блокировки. Аватар, ник и дата привязки сохраняются и показываются в профиле.
- При запуске Discord-бот создаёт недостающие роли и служебные каналы, настраивает webhook-уведомления и публикует кнопку в `#получить-код`. По нажатию бот отправляет уникальное приглашение в личные сообщения; оно действует 7 дней, запрашивать код можно раз в 24 часа, а созданный аккаунт всё равно ожидает активации ГКА.
- Slash-команды существующего бота: `/profile`, `/cases`, `/rating`, `/report`, `/absence`, `/tasks`, `/calendar`. Команды сверяют активный привязанный аккаунт и соответствующую Discord-роль; `/absence` сохраняет заявку в общей базе, а кнопка подтверждения поручения доступна руководству и проверяется сервером.
- ГКА может исправить отображаемое имя участника в разделе состава; новое имя синхронизируется с ником Discord.
- Discord-webhook оформлены с эмблемой Коллегии и уведомляют о заявках на вступление (включая регистрацию по одноразовому коду), отчётах на повышение, результатах экзаменов, выговорах и смене состава.
- Уведомления в Discord отправляет отдельный модуль `webhooks.mjs`: очередь на каждый канал, повторные попытки с нарастающей паузой, корректная обработка лимита запросов Discord (`retry_after`) и ошибок 5xx, таймаут на попытку. Панель «Discord и уведомления» в разделе «Отчётность» показывает состояние OAuth, бота, ролей и каждого канала, а кнопка «Проверить» отправляет тестовое сообщение. Сбой канала больше не мешает сохранению заявки.
- Одноразовые инвайты, статусы аккаунтов, серверные сессии и защита изменяющих запросов от CSRF.

Документы из архива предназначены для черновиков: перед публикацией проверьте факты, доказательства и актуальность нормы на сервере. Пять новых правовых текстов размещены отдельно в `data/laws` на основании материалов, предоставленных руководством. Поиск и тесты доступны в портале; при обнаружении противоречий руководствуйтесь официальной действующей редакцией форума.

## Отчётность в Google Sheets

Месячный экспорт доступен ГКА и ЗГКА. Он показывает состав и помесячные показатели из базы портала. Отдельная оперативная аналитика доступна за 7/30/90 дней и всё время. Личные email, Discord ID и пароли в Google Sheets не отправляются. Время онлайн не измеряется. Источник истины — портал: редактирование таблицы не меняет данные EXE.

Кнопка «Скачать CSV» сохраняет текущий отчёт локально, в том числе если Google Apps Script ещё не настроен. Синхронизация с Google Sheets остаётся отключённой, пока сервер не получит URL веб-приложения и секрет.

Для подключения:

1. Создайте Google Sheet и откройте **Расширения → Apps Script**.
2. Вставьте код из `integrations/google-sheets/Code.gs`.
3. В **Настройки проекта → Свойства скрипта** добавьте `SPREADSHEET_ID` (из адреса таблицы) и `SYNC_TOKEN` (случайная строка не короче 32 символов).
4. Разверните скрипт как веб-приложение от своего аккаунта Google и скопируйте URL развёртывания вида `https://script.google.com/macros/s/.../exec`. Скрипт проверяет секрет из тела запроса перед записью. Не публикуйте секрет и не отправляйте его в чат.
5. На серверном ПК добавьте URL и тот же секрет в локальный `.env`:

   ```dotenv
   GOOGLE_SHEETS_WEB_APP_URL=https://script.google.com/macros/s/ВАШ_ID/exec
   GOOGLE_SHEETS_SYNC_TOKEN=ВАШ_СЛУЧАЙНЫЙ_СЕКРЕТ
   GOOGLE_SHEETS_SYNC_INTERVAL_MINUTES=60
   ```

6. Перезапустите серверный EXE. Кнопка в «Отчётности» запускает синхронизацию вручную; при настроенном подключении текущий месяц также обновляется по расписанию. Минимальный интервал — 5 минут, максимальный — 1440 минут. Скрипт создаёт листы «Состав», «Отчётность» и «Журнал синхронизации»; повторная отправка обновляет строки по месяцу и ID сотрудника.

Google Sheet имеет право получать только предусмотренный отчёт; обратной синхронизации нет. Храните таблицу и секрет под контролем руководства. Если приложение было скопировано или секрет опубликован, замените его в свойствах скрипта и `.env`.

## Проверки

```powershell
npm.cmd test           # модульные тесты сервера и модуля уведомлений
npm.cmd run check      # полный набор проверок интерфейса и сервера
npm.cmd run check:ui   # аудит разметки/стилей и смоук-тест интерфейса в DOM
npm.cmd run check:server # сквозная проверка отдачи файлов и endpoint'ов на живом сервере
npm.cmd run preview    # скриншоты интерфейса в установленном Chrome (папка preview)
```

Что именно проверяется:

- **Аудит интерфейса** (`tools/audit-ui.mjs`) — сверяет связку HTML/CSS/JS: каждый `#id`, к которому обращается скрипт, существует в разметке; каждый класс, который создаёт скрипт, описан в стилях; все иконки и разделы на месте; в HTML нет стилей и кода; данные лежат в JSON; в файлах фронтенда нет секретов.
- **Смоук-тест интерфейса** (`tools/smoke-ui.mjs`) — поднимает `advokate.html` в jsdom с подготовленными ответами API, запускает модули, открывает все разделы и проверяет, что портал стартует без ошибок JavaScript и витрина наград рисует 10 записей.
- **Сквозная проверка сервера** (`tools/check-server.mjs`) — запускает портал на свободном порту и проверяет отдачу CSS/JS/JSON, защиту от обхода каталога, заголовки CSP, диагностику Discord и реальную отправку проверочного webhook.
- **Модульные тесты** — серверные сценарии (`server.test.mjs`) и доставка уведомлений (`webhooks.test.mjs`).

## Проверка Discord

Для проверки настроек Discord без запуска портала:

```powershell
node tools/discord-check.mjs             # форматы значений в .env
node tools/discord-check.mjs --network    # токен бота, сервер, роли и доступность webhook
```

Скрипт не печатает секреты: он показывает только маски и подсказки. С флагом `--network` он входит ботом в Discord, проверяет сервер и его роли, а также обращается к каждому webhook, чтобы убедиться, что канал не удалён.

## Публикация в интернете

Для внешнего доступа разместите приложение за HTTPS reverse proxy. Не выставляйте сервер напрямую в интернет по HTTP. Установите в окружении `NODE_ENV=production` и `COOKIE_SECURE=true`; задайте необходимые переменные до запуска:

- `HOST` — адрес привязки Node.js; для reverse proxy обычно `127.0.0.1`.
- `PORT` — порт приложения (по умолчанию `3000`).
- `DISCORD_WEBHOOK_APPLICATIONS` и `DISCORD_WEBHOOK_EXAMS` — необязательные Discord webhook URL. В webhook заявок приходят также регистрации стажёров по коду-приглашению; задавайте URL только в серверном окружении или локальном `.env`, никогда не в HTML.
- `DISCORD_WEBHOOK_LOGS` — необязательный webhook журнала решений, изменений состава и выговоров. Настройте его на закрытый канал для руководства. Для личного сообщения о выговоре также требуется `DISCORD_BOT_TOKEN` и привязанный Discord-аккаунт сотрудника.
- `DISCORD_WEBHOOK_CALLS` и `DISCORD_WEBHOOK_BAILS` — отдельные webhook URL для отчётов о вызовах и залогах соответственно. Эти отчёты отправляются только в настроенный для их типа канал, а не в журнал руководства.
- Голосовой канал статуса автоматически показывает `🟢 Активен · X мс` или `🔴 Недоступен · X мс`; отдельный webhook статуса не требуется.
- `DISCORD_WEBHOOK_HELP` — необязательный webhook канала помощи граждан. Бот создаёт его на канале `🆘-помощь-адвокатам`.
- `DISCORD_CATEGORY_PORTAL`, `DISCORD_CATEGORY_MANAGEMENT`, `DISCORD_CATEGORY_CASES` — необязательные названия категорий для основных каналов, руководства и приватных обращений.
- `DISCORD_HEALTH_INTERVAL_MS` — интервал проверки состояния в миллисекундах; по умолчанию 300000 (5 минут).
- Discord OAuth: задайте `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` и `DISCORD_REDIRECT_URI` (точный callback `/api/discord/callback`).
- Discord bot: задайте `DISCORD_BOT_TOKEN` и `DISCORD_GUILD_ID`. Пригласите бота с OAuth2 scopes `bot` и `applications.commands`; ему нужны права управления ролями, каналами и webhook. Поставьте роль бота выше управляемых ролей. ID ролей создаются автоматически и хранятся в базе портала; уже заданные `DISCORD_ROLE_*` сохраняются. Команды регистрируются в указанном сервере при запуске бота.

Бот также должен иметь право управлять никнеймами для синхронизации имён. В Discord Developer Portal добавьте callback URL в OAuth2 Redirects для привязки Discord. Пользователь должен состоять на сервере и разрешить личные сообщения от участников сервера, иначе бот не сможет доставить код. Секреты не отправляйте в чат и не сохраняйте в HTML.

Локальный `.env` не добавляется в Git. Ограничьте доступ к файлу базы данных и регулярно делайте резервные копии при остановленном сервере.
